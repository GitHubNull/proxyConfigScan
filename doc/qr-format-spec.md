# 二维码格式规范（APP 解析端 / Burp 插件生成端 共同遵守）

> 本文档是二维码内容的**唯一事实源**。任何一端变更格式必须先改本文档。

## 1. 格式定义

二维码载荷为一个 **URI**，采用 RFC 3986 的 `http` scheme 表达代理配置：

```
http://host:port
```

| 组成 | 规则 |
|---|---|
| scheme | 必须为 `http`（小写）。登记值见 §3 |
| host | IPv4 地址 / IPv6 地址（方括号包裹，RFC 2732）/ 域名（reg-name）。**本期实际场景只能是 IPv4 局域网地址**（Burp 代理监听地址），但解析端按完整规则校验 |
| port | 十进制 1–65535。**缺省 8080** |
| userinfo/path/query/fragment | 不允许携带语义；解析端忽略并记录日志 |

## 2. 双方遵守条款

### 2.1 生成端（Burp 插件）

1. 取 Burp Proxy listener 的绑定地址与端口，组装为上述 URI 后编码为 QR（纠错级别 ≥ M）。
2. 绑定地址为 `0.0.0.0` 或 `127.0.0.1` 时，**必须替换为本机局域网 IPv4 地址**（如 `192.168.x.x`）；无法确定局域网地址时给出明确错误提示，禁止生成不可达二维码。
3. host 为 IPv6 时必须以 `[...]` 包裹。
4. 端口必须显式给出（即使恰为 8080），避免歧义。

### 2.2 解析端（移动 APP）

1. 按 RFC 3986 解析 URI；scheme 大小写不敏感，归一为小写比较。
2. host 校验：IPv4 每段 0–255；IPv6 由 `Uri` 解析器去括号后按标准校验；域名按标签规则（1–63 字符，字母数字连字符，不以连字符首尾）+ 总长 ≤253。
3. port 校验：1–65535 整数；缺省补 8080。
4. **局域网提示**：host 非公网保留段（10/8、172.16/12、192.168/16、169.254/16、127/8）且非常用内网域名时，UI 弹确认"目标似乎不在局域网"。
5. 非法码给出中文错误文案，不崩溃、不静默放行。
6. 解析成功后交 VPN 引擎前，重复 §2.2.2–2.2.3 的完整校验。

## 3. scheme 登记表

| scheme | 状态 | 说明 |
|---|---|---|
| `http` | **本期支持** | Burp 代理配置 |
| `https` | 预留 | 语义未定，解析端报"暂不支持" |
| `socks5` | 预留 | 未来支持上游 SOCKS5 时启用 |
| 其他 | 拒绝 | 报"无法识别的二维码格式" |

## 4. 示例

合法：

| 二维码内容 | 说明 |
|---|---|
| `http://192.168.1.10:8080` | 标准局域网场景 |
| `http://192.168.1.10` | 缺省端口 → 8080 |
| `http://[fe80::1]:8080` | IPv6（本期罕见但合法） |
| `http://proxy.lan:8080` | 内网域名 |

非法：

| 二维码内容 | 拒绝原因 |
|---|---|
| `https://192.168.1.10:8080` | scheme 未启用 |
| `http://192.168.300.1:8080` | IPv4 段越界 |
| `http://192.168.1.10:0` / `:70000` | 端口越界 |
| `http://:8080` | host 缺失 |
| `192.168.1.10:8080`（裸文本） | 非 URI；解析端可容错补 `http://` 后重试一次 |
| `http://user@192.168.1.10:8080` | 携带用户信息，拒绝 |
| `http://192.168.1.10:8080/path?x=1` | path/query 无语义，解析端**忽略**后正常解析（host:port 仍须合法） |

2. 同步通知另一端实现。
3. 双方各自的合法/非法用例集（APP 端 `test/unit/dart/`，插件端迭代期补充）随格式变更更新。
